# 需求方案：AI 辅助答辩质检（模拟评委提问 + 自动评分）

> 决策人：谢涵宇（某基金公司交付）

## 一、原始需求（人给的原文要点）

1. **有价值的数据**：评委问题、学员回答详情、导师点评与补充。
   区分**静态的应届生数据**和**持续更新的社招数据**。
2. **AI 辅助质检**：新人提交阶段总结材料后，AI 基于材料模仿评委生成问题，
   多轮提问并对回答自动评分。目的是让新人结合过往答辩记录查漏补缺。
3. **数据来源**：历史答辩问答记录（提取问题和评估标准）+ 业务手册
   （业务基础知识如股债基、回购；功能类用户手册如风控、清算）。
4. **后续**：本地调试 → 服务器部署给团队共享。

## 四、技术方案

### 4.1 存储：新建 `app/data/defense/`

**为什么不塞进现有知识库**：

- 答辩记录是**结构化**的（问题/回答/点评三者关联），拆成文本块会丢关联；
- `chunks.jsonl` 的 `id/path/chunk/text` 四字段**不能改**（AGENTS.md 硬规矩）；
- 要按月增量追加，文档形式不好做去重和版本。

```
app/data/defense/
  ├─ records.jsonl      # 一条答辩记录一行（追加式）
  ├─ index.json         # 索引元数据（含向量）
  └─ criteria.json      # 评分标准（领导给的 + 从点评提炼后人工确认的）
```

记录结构草案：

```json
{
  "id": "d_001",
  "type": "应届生 | 社招",
  "batch": "2026春招",
  "role": "交付工程师",
  "question": "请说明 O-order 部署的关键步骤",
  "answer": "学员回答原文…",
  "comments": [{"by": "导师", "text": "点评与补充…"}],
  "tags": ["部署", "O-order"],
  "score": null,
  "ts": "..."
}
```

**追加式 vs 覆盖式的选择**：倾向**追加式**（`records.jsonl` 往后 append）。
理由：每月导出通常只含本月新增；追加不必重算历史；某月数据有问题只删那一段。
**前提要确认「每月是只有新增还是全量」**——若是全量，导入时按 `id` 去重。

### 4.2 流程：模拟提问 + 评分

```
新人上传阶段总结材料
   ↓
【检索】从答辩库找同类问题（复用现成 BM25 + 向量 + 重排）
   ↓
【生成】模型模仿评委出题，结合：历史评委提问风格 + 新人材料 + 业务手册范围
   ↓
【多轮】新人回答 → AI 追问 → 再答 → 再追问（3~5 轮）
   ↓
【评分】对照 criteria.json 打分 + 给改进建议
```

多轮对话**已有能力**：`/api/kb/{kb_id}/ask/stream` 支持 `hist` 参数。

### 4.3 业务手册

直接建知识库，**不改代码**。现有导入支持 Word/PDF/PPT/Excel、OCR、图片提取。

**唯一的坑**：现在检索是**单库**的（在 `kb_id` 范围内 BM25 + 向量 → 融合 → 重排）。
若演练要同时用「答辩记录」+「业务手册」，需要**跨库联合检索**。两条路：

1. 业务手册也导进答辩库（简单，但资料混杂）
2. 加「多库联合检索」开关（干净，但要改 `kb.py` 检索层）

→ 倾向方案 2，但**这是唯一需要动核心检索的地方**，必须人确认后才做。

## 五、风险与约束

### 5.1 网关只有约 2 路并发（实测）

本文件所在会话实测：5 个并发请求，2 个立即返回、3 个卡 18 秒；
不报错不限流，但延迟两极分化。详见 CHANGELOG「15:05（11-06）」条目。

**影响**：一次答辩演练要跑 3~5 轮多轮对话，5 个新人同时练会严重排队。
**换服务器解决不了**——瓶颈在网关，不在服务器。

**对策（待定）**：演练做成**异步任务队列**，提交后排队，完成后通知，
不抢实时问答的通道。

### 5.2 评分可信度是最大的产品风险

技术都能做，但如果评委觉得 AI 打分离谱，功能就没人用。
**必须先验证再开发**（见第六节）。

### 5.3 历史点评是散文不是分数项

“这位同学对 XX 理解还不够”这类文字**不能直接当评分依据**。
建议先用模型从历史点评提炼评分维度，**人工确认一遍再固化**。

## 六、建议的开发顺序

### 第 0 步：可行性验证（**先做这个，不写业务代码**）

拿 3 条真实答辩记录（问题 + 学员回答 + 导师点评），让模型：

1. 模仿评委，针对回答再提 2 个追问；
2. 给这个回答打分并写评语。

然后和导师真实点评对比：**追问像不像评委？评语和导师说的是不是一回事？**

- 对得上 → 方案成立，进入开发；
- 对不上 → 先解决评分标准问题，再谈开发。
