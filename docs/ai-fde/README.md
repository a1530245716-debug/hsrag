## 一页结论

- **现状**：FastAPI 单进程 + Python BM25 + 2 路重排。实测 10 并发 p95 已到 42 秒，100 并发 p95 315 秒，单进程不可用于 100 人在线。
- **根因**：检索/重排/推理都在 Web 请求进程里；同步 SSE 占线程池；状态在内存和本地文件。
- **路线**：**RAGFlow 做检索内核 + FastAPI BFF 保留业务 + 内部 LLM 网关 + Redis/Postgres/MinIO + Docker Compose**。
- **学习**：用 RAGFlow 练深度，用 Dify 沙箱补广度，用本项目真实场景做案例；所有结论用评测和压测量化。
- **原则**：不为了并发重写成 LangChain；不一次性大爆炸重写；用 BFF 适配层保证随时可回退。

## 当前项目基线（2026-11-11）

- 知识库：56,426 块；假模型 2.3 秒/答；16 vCPU 开发机。
- 10 并发：p95 42.4 秒；30 并发：127.3 秒；50 并发：173.3 秒；100 并发：315.5 秒。
- 100 并发时 97% 请求 TTFT ≥ 120 秒，29 次重排排队超时，32 次大模型 90 秒假超时。

详细数据见 [01-需求与现状评估](01-需求与现状评估.md)，复现命令见 [04-PoC实施与评测](04-PoC实施与评测.md)。
