# 05 · 生产部署与运维

> 对应 FDE 流程的**上线 + 运维**阶段。目标：在内网稳定运行 100 人在线，出问题能定位、能回滚。

## 1. 服务器规格

| 项 | 最低 | 推荐 | 说明 |
|---|---|---|---|
| CPU | 8 vCPU | 16 vCPU（32 更好） | x86_64，AVX2；不要超卖 |
| 内存 | 16GB | 32GB（64GB 更稳） | RAGFlow + ES/MinIO/MySQL/Redis + BFF |
| 磁盘 | 100GB SSD | 200~500GB SSD/NVMe | 本地盘；索引、备份、日志 |
| 系统 | Ubuntu 22.04/24.04 LTS | 公司标准 Linux | 不建议 Windows Server |
| Docker | 24+ / Compose v2 | 同上 | RAGFlow 通常以容器交付 |
| 网络 | 千兆内网、固定 IP | 内网 DNS + 内部 CA | 只开 443 |
| GPU | 无 | 可选 T4/A10/L4 | embedding/rerank 加速 |

## 2. 网络与接入

```
办公网/VPN → 内网 DNS → Nginx 443 → BFF 127.0.0.1:8000
                                  → RAGFlow（内网端口，不对外）
                                  → LLM 网关（内网地址）
```

- 应用端口只监听 `127.0.0.1` 或内网地址；不要直接暴露 8000。
- Nginx/公司网关必须：`proxy_buffering off`、`proxy_read_timeout >= 300s`、`client_max_body_size >= 100m`、HTTP/1.1、`X-Forwarded-*`。
- 参考配置：`docs/ai-fde/poc/nginx-sse.conf`。
- 浏览器代理 PAC 要把内网域名加入直连例外，否则 SSE 可能被缓冲。

## 3. 密钥与配置

- **不要**把真实 Key/密码写进 Git。
- 使用 `.env` + 环境变量；文件权限 600；不同环境不同值。
- 模板：`docs/ai-fde/poc/env.example`。
- 至少轮换一次默认口令：RAGFlow 管理台、MySQL、MinIO、Redis、BFF 管理员。
- 服务器上不保留无关私钥/证书（如旧的隧道私钥）。

## 4. 资源与容量

- RAGFlow 的 Elasticsearch/MinIO/MySQL 都是内存/磁盘大户；先按 32GB 规划，压测后调整。
- 100 人在线、20~30 同时提问，先单机；不足时按层扩展：
  1. BFF 无状态，可加副本；
  2. RAGFlow worker 增加并发；
  3. ES 独立机器；
  4. embedding/rerank 独立服务/GPU。
- 不要一上来 K8s；Docker Compose 足够第一阶段。

## 5. 监控与告警

**必须有的指标**
- 应用：活跃问答、队列深度、429、错误分类、P95。
- 检索：检索耗时、空结果率、重排耗时/超时。
- LLM：TTFT、总耗时、429/5xx/超时、token 用量。
- 资源：CPU、内存、磁盘、连接池、ES 健康。
- 业务：日问答量、活跃用户、反馈率、Top 未命中问题。

**告警建议**
- 5xx/429 比例 > 5% 持续 5 分钟；
- P95 > SLO 持续 10 分钟；
- 磁盘 > 80%；
- ES 集群 yellow/red；
- 索引任务失败率 > 10%；
- 服务健康检查连续 3 次失败。

## 6. 备份与恢复

**备份对象**
- PostgreSQL（用户、知识库映射、日志）；
- MinIO（文档、图片）；
- RAGFlow 配置/数据集元数据；
- BFF `.env`（加密保管）；
- 旧系统的 `registry.json`、`chunks.jsonl`、`vectors.npy`（迁移期）。

**策略**
- 每日增量 + 每周全量；保留 4 周；
- 备份到 NAS/另一块盘；
- 每季度做一次恢复演练；
- 重建索引前先快照。

## 7. 升级与回滚

- 固定 RAGFlow/依赖版本；升级前在测试环境跑回归评测。
- 升级步骤：备份 → 停写 → 升级 → 冒烟 → 回归评测 → 恢复流量。
- 回滚包和旧镜像保留至少一个版本。
- BFF 用 feature flag 控制检索后端，出问题切回旧实现。

## 8. 故障手册（示例）

| 症状 | 可能原因 | 检查 | 处置 |
|---|---|---|---|
| 回答很慢 | 重排排队/LLM 慢/队列积压 | 看 P95、队列、重排超时日志 | 降级重排、限流、扩容 |
| 首 token 不出来 | 上游网关慢/连接池满 | 网关延迟、连接数 | 重试/切换 Key/限流 |
| 429 增多 | 超过 Key/网关并发 | 网关配额、活跃请求 | 排队、加 Key、降级 |
| 检索为空 | 索引未完成/权限/查询改写 | 文档状态、dataset、检索日志 | 等索引、修权限、调查询 |
| 上传后搜不到 | 解析失败/增量未完成 | 任务状态、worker 日志 | 重试解析、人工重导入 |
| 服务假死 | 线程池打满/同步阻塞 | 活跃线程、health 延迟 | 限流、重启、异步化 |
| 内存持续上涨 | 缓存无上限/索引泄漏 | RSS、缓存大小 | 设上限、重启、排查 |
| 权限越权 | BFF 校验遗漏 | 审计日志、接口 | 立即修复 + 审计 |

**通用排障顺序**：先看用户影响面 → 看最近变更 → 看监控四件套（延迟/错误/队列/资源）→ 缩小到某一层 → 回滚或降级。

## 9. 安全清单

```
[ ] 只开 443，应用端口不对外
[ ] 默认口令全部更换
[ ] Key/密码在环境变量，不进 Git
[ ] 文件权限 600，最小权限账号
[ ] 权限后端强制，有越权测试
[ ] 审计日志开启，保留期符合要求
[ ] 依赖漏洞扫描
[ ] 日志脱敏（不记录完整问题/答案中的敏感信息）
[ ] 备份加密/隔离
[ ] 外部分享材料已脱敏
```

## 10. 上线检查表

```
[ ] 服务器规格/磁盘/内存确认
[ ] 固定 IP、DNS、证书、防火墙
[ ] Docker/Compose 可离线安装
[ ] RAGFlow/BFF/网关/Redis/Postgres/MinIO 启动正常
[ ] Nginx SSE/超时/上传上限验证
[ ] 管理员口令/密钥已更换
[ ] 监控/告警/日志轮转
[ ] 备份任务和恢复演练
[ ] 回滚包和回滚演练
[ ] 用户培训/通知
[ ] 7 天观察期负责人
```
