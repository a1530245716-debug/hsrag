# 06 · 上线推广与交接

> 对应 FDE 流程的**推广 + 交接**阶段。上线不是终点；FDE 的价值在于用户真正用起来、能复制到下一个项目。

## 1. 试点计划（2 周）

**选人**
- 5~10 个真实用户：新接手项目的实施、现场负责人、老带新导师。
- 至少 2 个“愿意提意见”的人，不要只选熟人。

**选场景**
- 3 个高频场景：项目认知、环境信息、部署/排查。
- 每个场景准备 5 个标准问题和期望答案。

**节奏**
- 第 1 天：15 分钟培训 + 发速查卡。
- 第 1 周：每天看一次使用记录和反馈，快速修明显问题。
- 第 2 周：收集 10 条真实问题，补知识库/提示词。
- 结束：输出试点报告，决定是否扩大。

## 2. 培训材料

最少三样：
1. **一页纸速查**：入口、登录、怎么问、怎么看引用、怎么反馈、找谁支持。
2. **3 个演示脚本**：每个场景一个真实问题 + 正确引用 + 注意事项。
3. **5 分钟录屏**：从登录到提问到点开原文。

培训时明确边界：
- 知识库没有的，系统应该拒答；不要诱导编造。
- 账号/密码等敏感信息按权限使用，不截图外传。
- 答案要回到原文核对，尤其是环境和配置。

## 3. 反馈闭环

- 每条回答保留“点赞/点踩 + 可选评论”。
- 每周汇总：Top 未命中问题、Top 点踩原因、Top 被引用文档。
- 反馈分类：知识缺失、检索没命中、回答错误、权限问题、体验问题。
- 明确处理时限：知识缺失 1 周内补；检索问题 3 天内调；权限当天。

## 4. 使用指标与 ROI

| 指标 | 说明 |
|---|---|
| 周活跃用户 | 至少提问 1 次的人数 |
| 日/周问答量 | 使用频率 |
| 首次解决率 | 无点踩/无转人工的比例 |
| 平均节省时间 | 自报或抽样对比“翻文档”耗时 |
| Top 未命中问题 | 知识库建设方向 |
| 引用点击率 | 用户是否核对原文 |
| 满意度 | 点赞率/问卷 |

ROI 写法示例：
> 试点 10 人、2 周、320 次问答；平均每次节省 8 分钟，合计约 42 小时；未命中问题 18 条，已补 12 条。

## 5. 交接清单

**文档**
- 架构图、数据流、部署拓扑；
- 部署手册、升级/回滚手册；
- 运行手册、故障手册、告警说明；
- 权限矩阵、账号清单（不含密码）；
- 备份/恢复步骤；
- 评测集与最近一次报告；
- 已知问题与路线图。

**账号与权限**
- 服务账号、数据库、MinIO、Redis、网关 Key 的保管人；
- 管理员账号交接；
- 紧急联系人。

**演练**
- 新人按手册独立部署一次；
- 模拟一次检索故障和一次 LLM 超时；
- 恢复一次备份。

**交接验收**
```
[ ] 新人能独立启动/停止/重启
[ ] 新人能看监控定位一次慢请求
[ ] 新人能完成一次增量导入
[ ] 新人能执行一次回滚
[ ] 文档中的命令都实际跑过
```

## 6. 推广到更多项目

**可复制的东西**
- Docker Compose/部署脚本；
- 评测集模板和压测脚本；
- 权限模型和 BFF 适配层；
- 培训材料/速查卡；
- 运维手册/告警规则。

**每个新项目要重新评估**
- 文档类型和解析难度；
- 数据敏感级别和权限；
- 并发和峰值；
- 网络/服务器资源；
- 业务验收标准。

**不要复制的东西**
- 客户数据、账号密码、内部域名；
- 针对某个项目的硬编码规则；
- 未脱敏的日志和截图。

## 7. 支持模型

| 级别 | 响应 | 例子 |
|---|---|---|
| P0 | 15 分钟 | 全站不可用、数据泄露 |
| P1 | 1 小时 | 大面积问答失败、权限异常 |
| P2 | 1 个工作日 | 单库检索差、解析失败 |
| P3 | 排期 | 体验优化、新功能 |

明确“谁值班、怎么升级、什么情况回滚”。

## 8. 变更管理

- 任何检索/模型/提示词变更，先跑回归评测；
- 配置和索引版本化；
- 变更记录：时间、人、内容、评测结果、回滚点；
- 大变更选低峰期，提前通知用户。
