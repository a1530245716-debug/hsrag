# 08 · FDE 学习与简历路线

> 目标：用这个项目完成从“交付/实施工程师”到“AI FDE（Forward Deployed Engineer）”的能力迁移，并形成可验证、可展示的作品。

## 1. FDE 是什么

FDE 不是纯算法岗，也不是普通驻场开发。核心是：

- **贴近客户**：理解业务、梳理需求、管理预期；
- **快速原型**：用真实数据在几天内跑通端到端；
- **工程落地**：私有化部署、权限、集成、性能、安全；
- **可运维**：监控、SLA、故障处理、交接；
- **可复制**：把一个客户的方案沉淀成下一个客户能用的资产。

你的交付/实施背景是优势；缺的是 AI 工程深度、量化表达和公开作品。

## 3. 12 周学习计划

**第 1~2 周：环境与平台**
- Linux/Docker/Compose 基础；部署 RAGFlow；导入一个演示库。
- 产出：能独立启动/停止/排障；一篇部署笔记。

**第 3~4 周：RAG 内功**
- 切块、混合检索、重排、引用；建 20~50 题评测集。
- 产出：评测报告（Recall@k、P95、失败样本）。

**第 5~6 周：LLM 应用广度**
- Dify 做 2 个工作流/Agent demo；练 function calling、guardrails。
- 产出：2 个可演示 demo + 简短说明。

**第 7~8 周：BFF 集成**
- 在现有 FastAPI 里加 Adapter，一个库走 RAGFlow；权限在 BFF 校验。
- 产出：灰度上线的完整链路。

**第 9~10 周：性能与运维**
- 异步 SSE、限流、Redis 缓存；用 `tools/loadtest` 压 10/30/100。
- 产出：压测报告（改造前后对比）。

**第 11~12 周：作品集与复盘**
- 写 case study、英文 README、架构图、演示视频；做脱敏公开仓库。
- 产出：可投简历的作品集 + 5 分钟演示脚本。

## 4. 简历怎么写

**不要写**
- “使用 Dify/RAGFlow 搭建了 RAG 问答系统。”
- “熟悉 LangChain。”

**要写**
- 场景 + 架构 + 指标 + 取舍 + 交付结果。

示例：

> **企业级 RAG 交付（100 并发内网）**
> - 将检索/重排从单进程 Python 迁移到 RAGFlow + Elasticsearch，FastAPI BFF 异步代理 SSE；应用层 P95 从 315s 降到 X s，100 并发错误率 <1%。
> - 设计 BFF 适配层和权限模型，支持知识库归属/分享/只读；按 dataset 隔离越权访问。
> - 建立 50 题评测集与压测基线，覆盖召回、引用、拒答、P95；每次变更跑回归。
> - Docker Compose 私有化部署，接入内部 LLM 网关、Redis、Postgres、MinIO；输出部署/运维/故障手册。

量化建议：
- 并发、P95/P99、错误率、召回率、引用准确率；
- 文档数/块数、增量导入时间；
- 节省的人时/问答量（试点数据）。

## 5. 作品集仓库怎么建（重要）

**不要直接用现在这个私有仓库当作品集：**
- private 仓库 HR 点开是 404；
- 里面有客户名称、内部手册、域名/IP、真实资料；
- 公司交付代码的归属和公开权限需要确认。

**正确做法：新建一个脱敏的公开仓库**（例如 `rag-fde-demo`）：

```
rag-fde-demo/
  README.md              # 问题→架构图→技术栈→指标→运行方式→截图/GIF
  docs/
    architecture.md
    evaluation.md
    loadtest.md
  app/                   # 你有权公开的代码
  data/demo/             # 公开/合成样例文档
  docker-compose.yml
  .env.example
  LICENSE                # 只在你拥有版权时添加
```

**要点**
- 用**全新仓库或 orphan 分支**，不要在现有历史里删文件（历史仍可恢复）。
- 用脚本扫描客户名、公司名、内部域名、IP、账号、Key。
- 数据用公开/合成文档；截图用演示数据。
- README 顶部放：一句话价值、架构图、核心指标、演示链接/视频、技术栈。
- 如果代码属于公司，先获得许可；不允许就只公开 case study 和 demo，不放真实代码。
- 简历写法：`github.com/<you>/rag-fde-demo` + 一句话说明；私有仓库写 “private repo available on request”。

## 6. 面试会问什么

1. 为什么不用 LangChain？——编排库不解决并发；生产更看重可控和可观测。
2. 为什么选 RAGFlow？——文档解析、混合检索、增量、私有化；用 PoC 数据证明。
3. 100 并发怎么设计？——异步 API、外部检索、独立重排、限流/排队、每阶段 SLO。
4. 怎么评估 RAG 好不好？——评测集、Recall@k、引用、拒答、LLM-as-judge、人工抽检。
5. 权限怎么做？——BFF 强制、dataset 隔离、审计、越权测试。
6. 增量/删除/回滚？——任务队列、版本、幂等、灰度、备份。
7. 线上慢了怎么查？——每阶段延迟、队列、错误分类、trace、最近变更。
8. 客户数据不能出内网怎么办？——私有化、内部网关、脱敏、审计。
9. 怎么和客户沟通预期？——明确边界、拒答、试点、反馈闭环。
10. 你的最大失败/取舍？——用压测数据讲“先修哪个、放弃哪个”。
