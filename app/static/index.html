使用文档

一、这是什么

「项目智能问答助手」是一个文档问答系统。每个项目的资料（需求、方案、接口、部署手册、周报、遗留问题等）各自建成一个知识库，你用中文直接提问，它从这些文档里找依据、组织答案，并告诉你答案出自哪份文档的哪一段。

它不是你熟悉的普通聊天机器人：它只根据项目文档回答，不靠记忆瞎编。所以答案对错，你随时能点开引用核对原文。

二、登录

  1. 浏览器打开 https://rag.example.com（手机浏览器同样可用）。
  2. 在输入框里填管理员给你的 访问 key，点「进入」。没有用户名，key 就是身份。
  3. 不同 key 能看到的知识库不同。看不到某个项目，就是你的 key 没有被授权，找管理员开。

三、先选知识库

  1. 左侧列出你能访问的知识库，单击选中（蓝色高亮的就是当前库）。
  2. 一个知识库 = 一个项目的资料。选错了库，它当然答不上来。
  3. 切换库不影响历史记录，随时可换。

四、怎么提问（决定答案质量的关键）

底部输入框输入问题，回车发送。答案会逐字流式出现，生成过程中可以随时点 ⏹ 停止。

回答下面有两个按钮：↻ 换个回答 和 👍/👎。同一个问题每次检索到的片段、生成的措辞都会有点差别， 觉得这次答偏了、答浅了就点「换个回答」原地再抽一次——不会多出一条重复提问，也不用重新打字。 出错了（超时、生成失败、回答被截断）同一个按钮会变成 ↻ 重试。

两个最典型的问法，照这个路子问就行：

① 问具体流程 —— 「这件事怎么做」
demo升级的流程是什么样的
这类问题最好答：部署手册、操作步骤、变更记录会被直接命中，答案按步骤给出来。 每一步后面跟着右上角小标（如 1、3,4），对应下方引用的第几条，点开就能核对原文。
② 摸底一个陌生项目 —— 「我刚接手，这项目是什么、到哪一步了」
我是一个刚接手项目的小白，这个项目目前是什么进展，这个项目的内容是什么。
把自己的处境（刚接手、不了解）直接写进问题里是有用的。系统会把这句话拆成几条子查询 —— 项目内容、系统架构、当前进展、周报月报 —— 分别检索后再合成一份带时间线的介绍。 刚接手一个项目，先问这一句，比一个模块一个模块地摸要快得多。

几个让答案更准的习惯：

  • 问具体，别问宽泛。「OTRADE 部署要开哪些端口」比「怎么部署」更容易得到准确答案。
  • 带上文档里的说法。系统支持同义检索（问「佣金」也能命中「货币中介费」），但用项目里的原名命中率最高。
  • 几个小问题别堆在一起。「接口地址、超时时间、重试次数分别是多少」这种细项堆着问容易只答一半， 分开问更稳。但「总体摸底」是例外——上面第②种问法虽然长，系统会自己拆开查。
  • 答不上来就换问法。同一个意思换个说法再问一次，往往就出来了。
  • 问"发生过什么"时带上时间点。「10 月的周报里说进度到哪了」比「项目进度」准得多； 文档有新老版本时，系统会优先采信较新的那份。
  • 等太久时页面会显示秒数，超过 45 秒会提示「网关较慢，最多等 3 分钟」，这时候可以等，也可以点停止换个问法。

五、看引用（这是核实答案的唯一办法）

每个回答下方都有 📎 引用 N 个片段（点击文件名可打开原文件），点开就能看到系统实际用了哪几段文字。 每条引用前面有个蓝色序号，和正文里右上角的小标一一对应：正文写 3,4，就是引用区的第 3、4 条。

  • 点文件名 → 新窗口打开那份原文档，并直接定位到被引用的那一段，方便你逐字核对。 现在预览按原文档的排版渲染：标题层级、表格、文档里的插图都保留，和你在 Word 里看到的顺序一致。
  • 引用下方的缩略图是这段涉及的文档截图，点一下在当前页面放大，按 Esc、点空白处或右上角 ✕ 关闭，不会跳到别的页面。
  • 预览页里的图片同样可以点开放大。参数表、菜单路径这类"只在截图里"的信息，别只看文字，图也扫一眼。
  • 养成习惯：重要结论一定点开引用看一眼。答得对不对，文档说了算，不是模型说了算。

六、接着追问（上下文默认是关的）

输入框右边有个 💬 上下文：关 按钮。默认关闭：每次提问都独立理解，不受前面的对话影响。 这是故意的——交付场景里大部分是独立提问，旧对话带着只会让答案跑偏。

  • 要追问时先点一下，变成 💬 上下文：开。这时先问「这个接口怎么调」，再问「那它的超时怎么配」， 系统会结合上文理解「它」指的是谁。
  • 开启后底部会显示 🆕 清空上文（已记 N 轮），最多记最近 3 轮。换话题时点它清空，避免串题。
  • 关掉开关会顺手清空已记的对话，并给一句提示，不会悄悄丢掉。
  • 如果你问得太省略，它可能先把你的问题补全成完整问句再检索，并把补全结果显示出来，让你知道它"听懂"了什么。
  • 开关状态记在本机浏览器里，下次打开还是上次的选择。

七、告诉它答得好不好

每个回答底部有 👍 有用 / 👎 没用。

  • 点一下就会记录。管理员能在「📊 问答统计」里看到哪些问题总被差评、哪些问题系统压根答不上来。
  • 这不是客套功能：大家点的差评，就是知识库该补的内容。觉得没用就点，别客气。

八、往知识库里补内容

资料不全的时候，答案自然不准。补料有三种方式：

  1. 拖文件：把文件或整个文件夹直接拖到页面中间，松手即可加入当前知识库并自动建索引。
  2. 点「添加文件」：右上角按钮，选文件后批量加入。
  3. ✍️ 写内容：适合记录口头经验、临时结论、群里聊出来的要点。点开就是一个空白编辑器，直接写字，也可以 Ctrl+V 粘贴截图（会自动存成图片一起入库），写完点「保存到知识库」。
    还可以用它继续编辑已有笔记，不必每次新建。

文件越多，首次建索引越久（大项目几分钟到十几分钟），页面会显示进度，等它跑完再提问。

九、在手机上用

  • 地址相同，手机浏览器直接打开。
  • 左上角的 ☰ 打开知识库列表，选好会自动收起，把屏幕让给对话。
  • 粘贴截图、看引用、点反馈都支持。

十、常见问题

问：它说「没有找到相关内容」？
两种可能：知识库里确实没有这方面资料；或者你的问法和文档里的用词差太远。先换个说法再问一次，还不行就说明该补文档了。
问：提示「大模型调用失败」，下面还列了一堆片段？
说明检索是好的，只是负责生成的模型服务暂时不可用（内网网关波动或维护）。稍后点「↻ 重试」即可；这期间你仍然可以看列出来的片段自己找答案。
问：第一次提问特别慢？
服务刚启动时要把知识库索引进内存，第一次会慢一点，之后就快了。大项目首次可能等一两分钟，页面有提示。
问：答案看起来不对？
先点开引用看它到底依据了哪几段。常见原因是：引用的段落本身不完整、几个文档说法不一致、或者你的问题跨了好几个文档。这种情况换更具体的问法，或者把相关文档补全。
问：我追问「那它的超时呢」，它却当成一个新问题答了？
因为上下文默认是关的。点一下输入框右边的 💬 上下文：关，变成「开」再问，它就会结合上一句理解。
问：答案写到一半出现「正在接着写…」？
正常现象。单次输出有长度上限，撞到上限时系统会自动接着把它写完，你什么都不用做。 只有连续续写两轮还不够（问题范围太大）才会提示你拆开问。
问：答案里那些右上角小数字是什么？
引用角标，指下方引用区的第几条。看到不放心的地方，按数字去找对应那一条核对原文即可。
问：两个人同时问会互相卡吗？
不会。系统做了并发控制，多人同时用会排队处理，页面会显示当前阶段。
问：我看到的库比别人少？
key 决定了能看到哪些知识库。需要访问某个项目，找管理员给你的 key 加权限。

建立目的与背景

项目的核心定位：按项目建专属知识库，帮助实施人员及相关人员快速上手项目，并在项目后续实施与日常工作中随时问答检索。

实际工作中，每个项目的资料往往量大且分散——需求文档、设计方案、接口文档、部署手册、周报月报、环境配置、遗留问题清单等散落各处。实施人员要快速熟悉一个新项目，或在成长过程中随时查找某个知识点，靠翻海量文档很耗时。

这个工具把每个项目各自的文档统一建成独立的知识库（一个文件夹 = 一个项目知识库），通过检索 + 大模型智能问答，把"翻文档找答案"变成"直接提问得答案"，并给出引用来源。天然支持按项目切换、随时补充完善。

解决的痛点

  • 快速上手：新进实施人员面对海量项目文档，无需逐篇翻阅即可快速检索学习、掌握项目全貌，显著缩短上手周期。
  • 项目实施辅助：实施过程中遇到问题，直接提问即可定位相关依据，减少反复翻文档、找人问。
  • 按项目隔离：每个项目独立知识库，互不干扰，聚焦当前项目，避免无关信息干扰，响应更快。
  • 交接提效：人员变动或接手他人项目时，可依托已沉淀的项目知识独立掌握全貌与历史遗留问题，降低对个人的依赖。
  • 信息集中：日报、周报、环境配置、临时性文档等零散高价值资料统一入库，避免丢失与盲区。
  • 本地轻量、合规安全：本地私有部署，数据不出内网环境，适合金融企业项目环境。

用到的技术栈

  • 后端：Python + FastAPI + Uvicorn
  • 检索：中文分词（jieba）+ BM25 关键词检索 + 本地语义向量（bge-small-zh, ONNX） + Rerank 精排（bge-reranker-base int8）； 关键词与语义两路并行召回后融合，再按权威性/版本新旧/文件名命中加权，块级索引 + 内存缓存 + 启动预热
  • 文档解析：python-docx / python-pptx / openpyxl / xlrd / pymupdf(PDF) + 直接读 Office 内部结构定位图片； 支持 Word、Excel、PPT、PDF、文本、CSV、JSON 等
  • 文档内图片：按需从原文档解压（docx 的 word/media、pptx 的 ppt/media 等），转换后缓存； 矢量格式 EMF/WMF 自动转 PNG，所以引用区和预览页里的图都能直接看
  • 预览渲染：不靠外部 Office，直接按文档结构生成网页——标题层级、表格、图片位置都与原文档一致
  • 大模型：支持 Anthropic / OpenAI 协议的本地或云模型，走公司内网部署的大模型（如需外部可经 UIS 代理 key 接入）； 流式输出，单次输出撞上限会自动接着写，写完为止
  • 安全：访问口令鉴权、外网目录浏览禁用、登录有效期、知识库按 key 隔离
  • 前端：原生 HTML / CSS / JavaScript 单页，轻量无框架（阶段状态提示、停止/重试、流式输出、引用角标、图片放大）
  • 部署：本地私有部署，数据全部落在本机 app/data/（每库独立索引 + 语义向量），不出内网

知识库怎么来

两种建法，进同一个管道：

  • 指向本地文件夹：一个文件夹 = 一个项目知识库，适合资料已经很规整的项目。
  • 直接拖文件上传：先建一个空库，再把文件/文件夹拖进去，适合随手收集的零散资料。
  • 建好后增量索引：只处理新增和有改动的文件，没变的文件直接复用旧结果，所以补料之后重建很快。
  • 索引完成后自动补语义向量，页面会显示进度，跑完再提问效果最好。

架构简览

文件夹 / 上传目录 → 解析抽文本（同时记录每张图在文档里的位置）→ 分块 → 建立每库独立索引（chunks.jsonl）+ 语义向量库（vectors.npy）
