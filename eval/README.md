# 评测集

面向"刚接手项目的实施人员"的核心问答回归测试。改动检索、提示词、模型参数后跑一遍，
确认没有把原来答得对的问题改坏。

## 怎么跑

```powershell
# 服务要先启动（app\server.py 在 8000 端口跑着）
$py = "$env:USERPROFILE\anaconda3\envs\rag\python.exe"
& $py -u eval\run_eval.py
```

结果会写到 `eval/results/<时间戳>.json` 和同名的 `.md`（md 是给人看的，含完整回答）。

只跑前几条：

```powershell
& $py -u eval\run_eval.py -n 3
```

## 判定标准

每个案例有几个检查项：

- `must_include_any`：分组列表，**每组里命中任意一个词**就算该组通过；只要有一组全没命中就判 FAIL
- `min_len`：回答至少多少字，防止"答了个寂寞"
- 回答里出现 `⚠️ 回答未完`（被 max_tokens 截断或超时）一律判 FAIL

这套标准比较粗，只能拦住"答非所问"和"根本没答"，**不能替代人工看内容对不对**。
跑完建议翻一下 `.md` 里的实际回答。

## 加新案例

直接往 `xinyuan_cases.json` 的 `cases` 里加一条：

```json
{
  "id": "xy-07",
  "topic": "分类",
  "question": "实际会怎么问",
  "expect": "人话描述：一个合格的回答应该包含什么，避免什么",
  "must_include_any": [["关键词1", "同义词1"], ["关键词2"]],
  "min_len": 300
}
```

`expect` 不会被脚本检查，是给人和后续模型看的——写清楚"什么叫答得好"，
以后改提示词或换模型时这是最重要的参照。
