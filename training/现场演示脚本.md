# 现场演示脚本：两个独立场景

> 配套 PPT：`training/项目智能问答助手-使用培训.pptx`
> 演示素材：`training/demo/演示资料-上线检查清单.docx`、`training/demo/谢涵宇-转正答辩.pptx`
> 备用虚构素材：`training/demo/答辩演示-智能交易平台.pptx`
> 两个场景相互独立：
> - **场景 A · 知识库问答**：新人项目交接、日常查部署/环境/操作。
> - **场景 B · 模拟答辩**：培训后的考核、导师模拟提问、新人自测。
>
> 可以只演示 A，也可以 A+B 连着讲，但**不要把 B 讲成 A 的第 7 步**。
> 建议时长：A 约 12–15 分钟；B 约 6–8 分钟。
>
> PPT 第 19 页起是附录（成功标准 / FAQ / 会后行动），**现场不逐页讲**；
> 演示到 Demo B 结束，直接进入答疑。

# 场景 A：知识库问答（项目交接 / 日常查资料）

## A0 开场（2 分钟）

**说：**
> 今天不讲模型原理，讲清楚：为什么做、每个人怎么用、管理员怎么配。先走第一个场景——新同事小王接手 O32 项目，怎么用知识库问答快速找到答案。

**做：** 打开 PPT 第 1–4 页，停在“痛点”和“两个场景，一个底座”。

**强调：** 知识库问答解决“查资料”；后面的模拟答辩解决“练/考”，是另一件事。

## A1 注册与登录（2 分钟）

**说：**
> 系统用账号密码登录，不再是“一个口令就是身份”。新同事用公司邮箱注册，管理员在系统参数里决定新账号默认有哪些权限和知识库。

**做：**
1. 打开登录页；
2. 点“注册新账号”，**展示**邮箱/密码/验证码/邀请码字段（现场不提交，避免等邮件）；
3. 用提前准备好的 `<demo账号>` 登录。

**期望：** 登录成功，右上角显示演示用户名。

## A2 选库 + 第一个问题（5 分钟）

**说：**
> 一个项目一个知识库。选错库，系统就答不上来；共享给你的库是只读的，可以问但不能改。

**做：**
1. 左侧选择「业务手册（O32/资管培训）」；
2. 输入问题：
   ```
   O32交易所指令怎么下单？
   ```
3. 等待回答；如果出现“排队中”，顺带讲一下排队位次/预计等待，不要重复点发送。

**期望回答（关键词）：**
> 进入 **【指令管理】→【交易所指令】→<个股指令>**，选择基金/组合，输入证券代码、委托方向、价格和数量，确认后下达；后续走指令审批/分发。

**引用：** 应能看到 `基金投资管理系统O3.2用户手册V1.7(02.07.020)(1).pdf`。

**做：** 点正文角标 `[1]` 或引用文件名 → 打开预览 → 展示左侧文档目录、命中片段高亮。

**说：**
> 引用不是装饰。菜单路径、字段、版本是否正确，点开原文一眼就能核。这是知识库问答和通用聊天最大的区别。

## A3 追问：打开上下文（2 分钟）

**做：**
1. 点输入框右侧「💬 上下文：关」→ 变成「开」；
2. 追问：
   ```
   那审核和分发分别在哪做？
   ```

**说：**
> 默认关闭上下文，是为了避免旧对话把独立问题带偏；要追问就手动打开。换话题时点“清空上文”。

**期望：** 系统能结合上一问理解“审核/分发”指的是交易所指令流程，而不是当成一个全新的问题。

## A4 建库 + 上传：把团队经验沉淀进去（4–6 分钟）

**说：**
> 知识库不只有“项目资料”，团队的上线检查清单、口头约定也可以沉淀。小王自己建一个库。

**做：**
1. 左侧「+ 新建知识库」→ 名称填「小王-上线检查」；
2. 从电脑选择/拖入 `training/demo/演示资料-上线检查清单.docx`；
3. 点「创建并建索引」；
4. 等页面显示索引完成（文件很小，通常很快；若慢，看备用方案）；
5. 在「小王-上线检查」库提问：
   ```
   上线检查清单的三项必查是什么？演示口令是多少？
   ```

**期望回答：**
> A. 数据库连接串；B. 报盘网关连通性；C. 回滚包校验。演示口令：**DEMO-2026-UP**。

**做：** 点引用，展示这份演示 DOCX 的预览。

**备用方案（索引慢）：**
> 不干等。先展示进度条，说明“真实项目首次建库要几分钟到十几分钟”，然后切回业务手册库继续讲；演示 DOCX 的答案可以在索引完成后再补。

## A5 反馈与重答（1 分钟）

**做：**
1. 点「↻ 换个回答」，说明是原地重答、不新增重复提问；
2. 点 👎，写一句原因，例如“希望补充审核/分发步骤”，说明这会进入问答统计，作为补资料线索。

**A 场景收尾：**
> 知识库问答就三件事：选对库、问清楚、点引用核对；团队经验持续往库里补。

# 场景 B：模拟答辩（培训考核 / 自测）

> **独立场景**：解决“新人培训结束后怎么练、怎么考”。入口、权限、产出都和知识库问答分开。

## B0 前置：管理员开通（2 分钟）

> 可以在 A 之前做，也可以现场用管理员账号演示。关键是让听众看到“答辩权限和知识库权限是分开的”。

**做（管理员账号）：**
1. 「更多 → 👥 用户管理」：展示添加用户、角色、**模拟答辩入口权限**；
2. 「📤 分配知识库权限」：同一用户有「智能问答」「模拟答辩」两列，分别勾选；
3. 「⚙ 系统参数设置」：展示**默认知识库**和**默认模拟答辩库**是两套，分开设；
4. 「大模型设置（全局）」：只展示协议/地址/模型字段，**不要展示 Key 明文**。

**说：**
> 分给问答，不等于分给答辩。没有答辩入口或没有可选依据库，用户就用不了模拟答辩。

## B1 上传 PPT，选模式与依据库（2 分钟）

**做：**
1. 右上角「🎓 答辩演练」；
2. 上传 `training/demo/谢涵宇-转正答辩.pptx`（26 页，真实转正答辩稿）；
3. 模式选「📖 练习模式」，题数选 3；
4. 出题依据库选「业务手册（O32/资管培训）」或含 O32/o-trade 资料的库；
5. 开始演练。

**说：**
> 上传的 PPT 决定“考什么”，依据库决定“参考答案从哪来”。这份转正答辩 PPT 涉及 O32、o-trade、现场实施，依据库选 O32/资管相关资料最贴。
> 如果问题偏 O32 操作、而不是 PPT 原句，这是正常的：系统是按 PPT 主题从依据库出题。

**注意：** 这份 PPT 含真实客户名，仅限内网培训演示；对外场合改用虚构版 `答辩演示-智能交易平台.pptx`。
**备用：** 如果现场上传/出题较慢，先翻到 PPT 第 13、18 页的截图讲“上传→出题→诊断”的形态，再回来实操，避免干等。

## B2 答第一题，看诊断（3 分钟）

**做：**
1. 答第一题（直接写两三句，不用长篇）；
2. 提交后展示：参考答案、依据、关键得分点。

**说：**
> 练习模式：每题答完立刻看解析，适合新人自测学习。
> 答辩模式：全程不给答案，全部答完统一看解析，更接近导师/评委现场提问。
> 导师用法：培训结束让新人用答辩模式做考核；日常让新人用练习模式反复自测。

**注意：** 现场只做 1 题，不要等完整报告；报告生成可能较久。

## B3 收尾：两套权限、两种用法（1 分钟）

**说：**
> 模拟答辩不是知识库问答的附赠功能。管理员单独开通入口和依据库；新人先用练习模式自测，培训结束再用答辩模式考核，逐题得分和总评可以作为培训评估的参考。

## 现场卡住时

| 现象 | 处理 |
|---|---|
| 一直排队 | 展示“第 N 位/预计等待”，说明这是容量保护；不要重复发送 |
| 模型很慢/无输出 | 先点引用看原文；切到另一个已准备好的问题；必要时停止重试 |
| 索引慢 | 只传小文件；先展示进度；切回已建好的业务手册库 |
| 权限不足 | 管理员现场在「用户管理/分配知识库权限」开通 |
| 429 | 同一个人同时超过 2 个，或队列满；等当前完成再试 |
| 模型/Key 报错 | 管理员检查全局模型；演示账号可改用「🧠 大模型本地回答」应急 |
| 没有「答辩演练」入口 | 管理员在「用户管理」开通答辩权限 |
| 答辩没有可选依据库 | 管理员在「分配知识库权限」勾选「模拟答辩」列 |
| 答辩出题离 PPT 太远 | 换更贴 PPT 主题的依据库；或直接用业务手册库讲“流程走通” |
